# Hands-on command coverage

This matrix tracks the commands taught by the curriculum where a walkthrough used to be necessary,
and calls out the boundary of the browser sandbox. “Supported” means the terminal parser, router,
and engine execute the behavior. Mutating lesson objectives are validated from repository state;
read-only commands such as `git show` are demonstrated with runnable examples because they leave
no state change for an objective validator to inspect.

| Curriculum area              | Lesson                                                                                                         | Supported behavior                                                                                                                                                                                                                           | Remaining gap                                                                                         |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Identity and settings        | `git-basics/git-config`                                                                                        | `git config [--global \| --local] [--get \| --unset \| --list] <name> [<value>]`; `user.name` / `user.email` sign commits, tags and reflogs; `init.defaultBranch`, `pull.rebase` and `pull.ff` take effect.                                  | No `--edit`, `--show-origin`, includes or system config; other settings are stored but do nothing.    |
| Amend the latest commit      | `everyday-git/git-commit-amend`                                                                                | `git commit --amend` with `-m`, `--no-edit`, or the message editor; `--reset-author`. The original author and parent are retained and `git reflog` records the replacement.                                                                  | Plain `git commit` without `-m` still asks for `-m` rather than opening the editor.                   |
| Inspect a commit             | `everyday-git/git-show`                                                                                        | `git show [<commit>]` prints metadata and the first-parent patch; merges get a combined (`--cc`) diff; `<commit>:<path>` prints that file's contents at the revision.                                                                        | No `--stat`, `--name-only` or other formats.                                                          |
| Rename a file                | `everyday-git/git-mv`                                                                                          | `git mv [-f] <source>... <destination>`: files, whole directories, several sources into a directory; staged content moves with the index entry.                                                                                              | No `-k` or `-n`. Untracked sources are refused, as in Git.                                            |
| Tag a release                | `everyday-git/git-tag`                                                                                         | Lightweight and annotated tags, with `-m` or the message editor; `git push --tags` / `git push <remote> <tag>`; `git fetch` brings tags down.                                                                                                | No tag signing or `git push --delete <tag>`.                                                          |
| Rewrite a branch             | `recovery/git-rebase-interactive`                                                                              | `git rebase -i` supports pick, reword, edit, squash, fixup (`-C`, `-c`), drop, break, label, reset and merge in the in-app editor; conflict continuation, skip and abort; editing and splitting commits while stopped.                       | No `exec` (no shell), `update-ref`, `--rebase-merges` or `--autosquash`.                              |
| Publish/synchronize branches | `remotes/clone-a-repository`, `remotes/push-a-branch`, `remotes/sync-with-remote`, `remotes/force-push-safely` | `git clone` of a lesson's simulated server; `git remote add / remove / rename / set-url / get-url`; fetch, pull modes, fast-forward-only checks, branch pushes, upstream setup, push rejection, `--force-with-lease`, `--force`, `--delete`. | Everything is offline: remotes live in the browser. No `src:dst` refspecs or `git clone <url> <dir>`. |

## Prioritization

Everything above runs end to end without a shell, network access, or an external editor: Git's
editor is a dialog in the page, and remotes (including ones learners clone or add) are simulated
in the browser. The remaining gaps are either impossible without a shell (`exec`) or rarely taught.

Run the corresponding package tests and `pnpm validate:content` after changing this matrix or the
lessons it describes.
